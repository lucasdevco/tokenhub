# Domain docs

This repository uses a single-context layout.

Before exploring domain concepts, read the root `GLOSSARY.md` if present. Before proposing architectural changes, read relevant ADRs under `docs/adr/` if present. Proceed when these documents do not exist; create them only when domain documentation is part of the requested work.

Use the glossary's vocabulary in specifications, tickets and code discussions. Surface conflicts with existing ADRs rather than silently overriding them.

The domain-modeling workflow maintains glossary terms and ADRs as decisions are resolved.
